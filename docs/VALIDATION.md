# dt-cue v0.3.0 検証記録

日付：2026-09-26

## 自動テスト：29件成功

既存22件に7件を追加。実装は外部BPMサービスを使わず、Worker内で3方式を実行します。

- 旧方式で未検出になる緩いアタック、小音量、強い冒頭アクセントの110 BPM信号を3方式で検出。
- 40／48／80／174／210／240 BPMのパルス列を誤差1 BPM未満で検出。既存の90／120／128／160 BPMも継続成功。
- 120秒の信号のうち先頭70秒が無音でも、後半の周期を検出。
- ランダム包絡、単発のアクセント、4秒未満の信号を未検出にし、理由を返す。
- ドラム・ベース・ハイハットを含むデモPCMで128 BPM付近を検出し、64 BPMの候補を保持。進捗が単調に進む。
- 1方式が棄権しても残る2方式の候補を統合。倍／半分の候補を混ぜない。
- 別候補を選ぶとBPMと位相を適用。手動BPMを解析完了で上書きせず、ファイル変更時に状態を初期化。

## Chromeでの操作確認

- 44.1kHzの緩いアタックのWAVを読み込み：発音間隔55.0、自己相関110.0、周期グリッド110.0から、110 BPMを自動選択。
- 小音量の110 BPM WAVを読み込み、110 BPMを自動選択。
- 無音WAVへ切り替えるとBPMと候補を消去し、未検出理由を表示。
- 自己相関の55 BPM候補を選択し、1ビート移動で1.091秒へ進むことを確認。
- デモ音源はブラウザが44.1kHzへリサンプリングしたPCMを使用。3方式の候補と自動統合を表示。
- BPM欄へ123.4を入力し「手動設定」へ切り替わり、自動統合で128 BPMへ戻ることを確認。
- 再生中のFFTで橙／水色／紫の棒とLOW／MID／HIGH凡例を確認。スクショを `docs/dt-cue-analysis.jpg` へ保存。
- AviUtl／After Effectsへ切り替えてFFT表示を確認。390px幅のiframe（有効幅375px）で解析後の3方式・候補欄を操作し、横のはみ出しがないことを確認。

検証音源は独自に生成した信号です。ユーザーが検出できなかった実ファイルは未提供のため、その音源での検証は含みません。4秒以上、40〜240 BPMの範囲を探索しますが、全曲の検出や可変テンポへの追従を保証するものではありません。

# dt-cue v0.2.0 検証記録

日付：2026-09-26

## 自動テスト：22件成功

v0.1.0の13件に加えて、以下の9件を追加しました。

- 既存のカスタムキーを優先して新しい10パッドの初期キーを適用し、重複しないこと。
- CUEのファイル別保持、終端・範囲外の拒否、消去。
- Note Off／velocity 0／連続Note Onでパッドを二重発火しないこと。
- CCの立ち上がり判定と連続値0〜127、不正メッセージの拒否。
- MIDI設定の破損・重複・チャンネル範囲とCC専用操作の検証。
- 明示接続、入力の追加・抜去、リスナーの重複防止、切断。
- MIDI許可の拒否と要求中のキャンセル。
- MIDI Learn中は演奏せず登録し、機器・チャンネルを区別して実行すること。音量CCの0と127。
- 空パッドは記録だけを行い、再押下で正確なCUE位置から再生し、以前のループを解除すること。

補助拡張の既存テストにもパッド10の配送と不正なパッド番号の拒否を追加。

## Chromeでの操作確認

- 10パッドを3種類の配置すべてで表示。
- デモ音源をPCM読み込みし、CUEを6秒／10秒へ記録。数字キー2からのパッド操作、CUE1からの再生を確認。
- 鉛筆→パッド3をクリック→キー登録。Space競合の表示、Qへの変更、操作を4ビートループへ変更し、Qでループを有効化。
- 再読み込み後にキーQとパッド操作が保持され、CUE位置は消えること。
- 6秒起点・128BPMの4ビートループ（B点7.875秒）、波形上のCUEマーカーを表示。
- MIDI設定の未接続／利用不可表示。権限処理とメッセージ配送は自動テストの模擬APIで確認。
- 390px幅のiframe（有効幅375px）で10パッドが2×5に並び、横のはみ出しがないことを確認。

**実MIDI機器、DAWとのポート共有、OSグローバルキー、音声出力の遅延・聴感は未検証です。** シミュレーションによる入力検証を実機試験とは扱っていません。
